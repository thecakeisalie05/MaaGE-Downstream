## Replica and Asynchronous Presentation

Session sends numeric block/biome columns, acknowledged-revision cell deltas and ordered removalsâ€”not light, meshes or live pointers. The replica owns lighting and geometry Jobs on immutable snapshots; obsolete results are rejected/rebased. Geometry can precede light refinement. Missing terrain obstructs, predictions are local overlays, and inventory is authoritative.

Near/forward terrain and collision cells have priority. First reveal advances eight directional sectors in two-ring groups, four concurrently. A bounded audit scans cached revisions once per batch to requeue loaded columns missing GPU geometry and pending mesh work (including empty meshes). Keep old presentation until replacements arrive; distance reduction retires Client meshes independently of transport unloads. No rendering wait for disk work. Video Settings Chunk Fade defaults to 750 ms (OFFâ€“2 s in 250 ms steps, persisted as `chunk_fade_ms`). Newly presented columns ease from full fog to normal shading, with the initial arrival area immediately clear and surrounding pending fades starting when terrain is revealed. Mesh revisions and prediction index views retain the column timestamp; retired columns start fresh on re-presentation. Direct mesh uniforms reuse the unused light-override component; fog blending preserves depth, alpha, and multiply neutrality across Metal, Vulkan and modern GL without additional draw calls or uploads.

## Rendering and Mesh Lifetimes

Common C owns scene/material plans, UI batching, surface tables, mesh preparation and translucency. Metal/Vulkan/modern GL own GPU upload, synchronization and display; legacy GL/Software expose fewer capabilities (`render.h`, `src/core/render/`).

Face merging requires compatible material, UV/animation and corner light/tint/AO. Irregular/sloped/flowing or varying-shade geometry retains separate quads; flat fluid tops merge only with identical height and compatible uniform shading. Immutable mesh bounds survive upload and support conservative culling without altering residency or reveal order. Packed vertices reference deduplicated surface records. Opt-in natural texture rotation hashes the owning world cell in the shared fragment shader, including merged quads, without extra world state or vertex/surface stride changes. Varying-shade rotated faces repeat UVs but remain unmerged. Translucency sorts triangles from one camera reference refreshed after half-block motion, then heap-merges chunk and transformed instance streams into contiguous index ranges; intersecting surfaces remain approximate. Incremental uploads, frame-slot ownership and deferred GPU retirement bound work.

Registered models share part/cuboid/provider APIs for mobs, block entities and item geometry. Chests use rear-hinged lids and inherited latches, with 64Ã—64/128Ã—64 sheets; copied poses are gated by replica readiness. Larger registered containers use background slices and paged 54-slot copied windows. Living instances retain interpolated body/head/limb poses, reset on discontinuity, and show accepted damage as ten-tick tint/recoil and eased death roll. Model-specific animation stays in callbacks. RGB overlays preserve alpha/light/fog within the 128-byte draw uniform; spawn eggs use ordered tinted layers. Model/item caches are resource-generation-owned.

Client LOAD resolves registered textures, padded rectangular model sheets, atlas, appearances and biome colors. Missing optional images use fallbacks. Shared shading handles foliage, AO, tint, fluid, fog, animated textures and foreground items; daylight scales sky contribution only.

F3+T stages atlas, GUI/font/HUD, environment and item resources on the render owner. Failure retains the prior complete generation. Successful publication swaps the replica appearance, invalidates obsolete meshes and rebuilds local geometry without waiting; logical IDs, pending actions and Server state survive. CPU views outlive borrowing Jobs (including shutdown), GPU resources retire through backend rules, and another reload waits while a retired generation remains. No re-registration, INITIALIZE or audio refresh. Resource-pack selection, alternate roots and shader reload are future work.

See [diagnostics](diagnostics.md) and [AGENTS.md](../AGENTS.md) for shared logging, filtering and error policy.

### Native Shaders V1

Options > Video Settings > Shaders owns the global switch (default OFF), Performance/Balanced/Cinematic presets, Custom classification, exposure and independent controls for directional shadows/quality/distance, RGB lights/quality, vegetation/wind, god rays/quality, sky, water/quality and underwater effects. Balanced is the default configuration. `[video] shaders_enabled`, `shader_quality` (0..3, Custom is 3), and `shader_exposure` (25..400 percent) accompany validated numeric `[shaders]` keys named after `maage_shader_settings`. Exposure buttons cycle 50..200 percent; applying a preset resets exposure to 100. Individual changes classify Custom unless all values match a preset. The existing atomic options writer persists all controls. The submenu scrolls at small GUI sizes and disables unsupported effects explicitly.

Vulkan advertises `MAAGE_RENDER_CAP_WORLD_EFFECTS` only with validated RGBA16F attachment/blend/sample/transfer support, sampled D32 depth, compatible descriptor/uniform limits and the existing 128-byte push constant contract. Metal retains its native SDR exposure/grading path; modern OpenGL, legacy GL and Software do not implement these six effects. Their controls report unavailable. `MAAGE_RENDER_CAP_NATIVE_SHADERS` and `MAAGE_RENDER_CAP_NATIVE_HDR` still distinguish grading from floating-point processing. Optional effect allocation failure logs the originating trace, removes the effects capability and retains baseline HDR grading; renderer recreation retries. Device loss retains its ordinary failure handling.

The six effects share one copied presentation frame: actual environment sun/moon directions, moon phase intensity, rain/thunder, camera, continuous visual time, smooth camera immersion and a borrowed numeric light list. They never mutate authoritative World lighting, propagation or simulation:

- **Directional shadows:** two/three/four stabilized orthographic cascades, texel-snapped centers, conservative geometry-bound culling, depth bias, cascade transitions and manual 2x2/3x3/4x4/5x5 PCF. The dominant actual sun or moon owns the map; darkness fades with its intensity. Opaque/cutout terrain and transformed scene instances cast; translucent surfaces do not. Cutouts use atlas alpha and identical wind deformation in the depth pass. Resident offscreen terrain and selected LOD surfaces can cast without expanding World interest. Low/Medium/High/Ultra request 1024/1536/2048/4096 texels per cascade. `MAAGE_SHADER_SHADOW_MIB` (default 128 MiB across frame slots) and native extent/framebuffer limits reduce resolution when necessary; bounded allocation diagnostics report the actual cascade count/resolution. Shadow distance is independent of view/LOD distance.
- **RGB lights:** finite inverse-square attenuation, smooth radius cutoff, receiver normals and baked-block-light compensation in the fragment shader. Numeric registered block emission/hues, fluid states, dropped/held block items, registered entity emission, burning entities and selected luminous block-fragment particles supply sources. The Client scans a bounded nearby confirmed block volume, merges sources on a two-block lattice and prioritizes by camera significance. Quality selects 8/16/32 sources; `MAAGE_SHADER_LIGHT_BUDGET` overrides retained capacity within allocation/native SSBO limits. The public list has no fixed light-count ceiling. Point lights are unshadowed and can leak through walls; static sources outside the nearby scan retain baked lighting.
- **Vegetation:** numeric material metadata selects rooted cross plants or canopy foliage, never names in render loops. Packed root weights keep plant bases fixed; coherent spatial waves/gusts use one visual clock and fade between 48 and 128 blocks. Source UV/random-rotation coordinates remain stable. Rigid trunks and ordinary geometry stay stationary. Distant leaf surfaces retain compatible metadata with the same fade.
- **God rays:** quarter/half-resolution atmosphere integration takes 8/16/24 view-ray steps, bounded by opaque depth and shadow distance. Shadow-enabled marching uses single-tap cascade visibility rather than multiplying the surface PCF cost at every volume sample. With shadows OFF, screen-space probes admit only sky-depth samples toward the projected dominant light. The post pass uses depth-weighted upsampling. Light behind the camera or below the intensity threshold skips the pass. This is conventional raster/depth-based scattering, without temporal history; screen-space fallback cannot recover offscreen occluders.
- **Sky:** an analytic Rayleigh-like angular term, forward Mie-like lobe, horizon color, actual celestial intensities and weather desaturation produce the HDR background. Direction-stable procedural stars fade at daylight. Existing sun/moon textures preserve the moon phase. Distant fog and water environment reflection use the same atmospheric function. Noncelestial dimensions retain their registered fog/ambient behavior.
- **Water:** numeric fluid metadata selects water while preserving existing still/flowing geometry and shoreline topology. Three directional gravity waves displace surface vertices with dispersion-based speeds and analytic normals; smaller capillary ripples and rain roughness animate highlights. Downward-only excursions preserve the maximum simulated shoreline; integer layer boundaries and submerged bottoms remain fixed. Near water retains its block grid, while geometric waves fade at 64–128 blocks for coarse LOD. Fresnel reflection, opaque-scene refraction, depth absorption/transmission, environment reflection and celestial/point illumination shade the surface. Medium/High add bounded 8/16-step screen-space reflection with sky fallback. Corrected camera-fluid immersion drives smooth world-only absorption/fog/distortion; hand and GUI follow processing. Legacy water overlays are bypassed only when the supported underwater path is enabled; lava and unsupported backends retain their existing rules. Refraction/reflection sample opaque geometry, so transparent objects and offscreen reflected content remain approximate.

The forward renderer still owns sorting, uploads, frame slots and retirement. Each effect-enabled slot adds a 576-byte std140 frame buffer, growable light SSBO, D32 shadow atlas, sampled opaque HDR/depth copies and a reduced-resolution HDR scattering target. Opaque rendering ends before color/depth copies; a compatible load pass resumes the existing sorted transparency traversal exactly once. Sampling never aliases the active color/depth attachment. The final world pass adds scattering/immersion, applies linear exposure and filmic tone mapping, and encodes into the existing SDR composition target. Foreground depth, hand, overlays and GUI retain their existing ordering. Panorama processing bypasses world effects. Global OFF submits no effect passes; individually disabled shadow/ray work is skipped and copy targets shrink to valid dummy resources when no consumer needs scene depth/color.

The GPU vertex and surface-table strides remain 32 bytes, and draw pushes remain 128 bytes. Material effect bits occupy the existing packed surface selector; root weight uses existing padding. Cascade bounds are prepared with mesh geometry on workers. Quality changes replace only affected resources in the next recycled frame slot; resize/recreation retains the adapter's existing fence/retirement boundary. LOD remains independent: selected coarse surfaces share lighting/fog/water and bounded shadow participation without requesting full-resolution geometry, Server streaming or simulation.

No bloom, G-buffer, physically based material system, point-light shadows, temporal reconstruction or ray-tracing extension is implied. Compilation/offline math and persistence checks do not establish graphical correctness, native validation-layer cleanliness or GTX 1080 frame-time targets. Windows Vulkan/modern GL builds are available locally; Metal and other platform builds require their native toolchains. GPU performance has not been measured for these effects.

### Independent Persistent Distant Terrain

Level of Detail offers Native LOD (default OFF), 16/32/64/128 distant chunks, and High/Balanced/Performance geometry quality. The full-detail radius remains the ordinary render distance, with a four-chunk transition margin when independent LOD is available. Server simulation distance remains independent. Camera clipping and atmospheric visibility use the distant radius; underwater brightness retains the full-detail radius, so distant terrain is not hidden behind near-stream fog. The native sampler currently supports the primary Overworld; other dimensions keep their ordinary full-detail radius rather than expanding Server interest to the distant radius.

`distant_lod.c` owns the independent system; `lod.c` retains the resident-surface helper and shared deterministic stagger policy. Stable aligned quadtree tiles span 1/2/4/8/16 chunks. One-chunk leaves retain 1-block sampling at the exact transition, reducing to 2/4-block patches farther away according to quality. Larger tiles use an 8x8 patch grid. Two-chunk split hysteresis reduces oscillation, and CPU allocations retain headroom across movement/distance changes. Hashed identities reuse resident tiles; only a changed camera chunk/settings rebuilds bounded selection, rather than scanning all distant coordinates every frame. Conservative tile-box frustum tests omit invisible submissions.

The single LOD Jobs worker serializes seeded terrain sampling, observed-column summarization, cache reads/writes, geometry construction and mesh preparation. Accepted contexts are independently bounded. Missing terrain precedes refinements, nearer/forward terrain gets priority, irrelevant requests are cancelled, and epochs/source revisions fence stale results. Render frames poll one completion and advance one upload by at most 256 KiB, without filesystem calls or waiting for workers. Resource reload cancels GPU epochs and copies new immutable face/color tables; older jobs retain their own copies. Primary-world CPU state survives dimension travel but cannot draw in another dimension. Save/Quit transfers GPU-detached CPU ownership to the existing lifecycle worker; final shutdown hides the window before joining.

Height/material-adaptive horizontal surface runs on coarse tiles, height-step sides, biome colors, atlas sampling, translucent water/shore faces, opaque edge skirts and macro canopy masses share ordinary world materials/depth/translucency ordering. Procedural canopies follow native biome tree density on stable cells; confirmed summaries preserve observed foliage height. They approximate forest silhouettes rather than reproducing individual trees. Parent geometry remains until all selected children have coverage. Detailed/predicted geometry suppresses coincident distant leaves, and an uploaded replacement gates the exact handoff. Already displayed, unfiltered exact meshes can survive unload for two extra rings while replacements fill. This is bounded retention, not an unlimited guarantee against missing terrain during teleportation or movement faster than generation. No temporal/geometric cross-fade or fully seamless transition is claimed.

`MAAGE_LOD_CPU_MIB` (default 16, range 1..256) bounds tile metadata; dynamic capacity derives from requested topology and that footprint. `MAAGE_LOD_GPU_MIB` (default 512, range 32..4096 subject to address width) bounds a conservative resident-plus-incoming mesh estimate. Unselected GPU geometry is evicted first; old geometry survives replacement publication. Native deferred-retirement/driver overhead is outside that estimate. `MAAGE_LOD_JOBS` bounds accepted tasks (default derived from CPU budget at roughly one context per 4 MiB, minimum two); one context can hold a worst-case tile mesh and preparation in addition to metadata. These are separate metadata/work/GPU admission controls, not a total process memory cap. Constrained budgets report partial coverage explicitly in F3/logs; 128 chunks is a selectable capability, not a measured FPS guarantee.

The world/dimension directory is `worlds/<UUID>/lod-cache/v3/d<dimension>/`. Fixed-size little-endian `MGLOD003` records validate a checksum over header and payload, world UUID fingerprint, dimension, seed, generator version, ordered content/material fingerprint, generation policy, coordinates and span. Samples store ground/material/biome, water plane/material and canopy plane/material. `.mgdl` files are derived sampled tiles; `.mgdo` files are confirmed, full-resolution column summaries with source revisions. Workers prefer observed summaries over procedural sampling. Invalid experimental bytes are regenerated; authoritative region/checkpoint files are never opened, removed or overwritten by this system. Temporary files are synced and atomically promoted. A changed observation invalidates its five derived ancestors before promotion, so interruption causes misses rather than preserving an obsolete derived tile over a new summary.

A bounded owner audit copies at most one changed, confirmed resident column per frame through `maage_world_copy_column`; accepted snapshots contain no predictions or live World pointers. A worker scans those immutable palette packets and persists the resulting surface summary. Observation completion invalidates only affected resident ancestors and pending uploads. Changes therefore become distant geometry incrementally rather than rebuilding the whole view. Backpressure defers capture; a column that disappears before the audit copies it may not be summarized. This is observation-based Client caching, not an authoritative Server change journal. Caves, overhang interiors, non-cube structures, thin details and exact tree species/shape are not faithfully encoded; cube constructions contribute their highest solid surface. A corrupt observation can only be recovered by procedural sampling or re-observation, not by reconstructing lost edits from this derivative.

F3 and Video Settings distinguish validated Vulkan HDR, SDR and unavailable backends; F3 shows shader preset/exposure, effects versus grade-only support and LOD residency/jobs/upload backlog/budget status. Five-second `maage.client.lod` summaries include counts by span, hits/generated/stale counts, worker wall time and estimated residency. Existing profiler CSVs include every shader control, selected-light count and effect capability alongside LOD and frame CPU work/tail latency. Worker and renderer wall times are explicitly **not GPU timestamps**.

The opt-in `MAAGE_BUILD_CLIENT_CHECKS=ON` CMake option provides `maage_client_lod_checks`, excluded from normal builds. It exercises shader presets/validation, INI bounds and actual save/load round trips, inverse/cascade transforms and culling, packed material flags/root anchoring, plus real content, tile selection, cache encoding, source revisions, palette snapshots, Jobs generation and shared frame plans without opening a window. Pass an absolute disposable directory to include disk corruption/interrupted-write/observed-edit checks; omit it for memory-only checks. Generated outputs belong under `cmake/` or `build/`. These checks do not validate native resource resizing, actual GPU upload cancellation, Metal compilation, graphics appearance or frame pacing.

### F2 screenshots and session archives

On Windows, press **F2** while MaaGE Client is focused to save a PNG of the
visible game client area in the selected instance's mapped `screenshots`
directory. Capture uses Windows' desktop composition; it is not a GPU
framebuffer readback. The game must be visible and unobstructed (no
minimization, occluding windows, or exclusive fullscreen). Screenshot errors
are logged as `maage.client.screenshot`; successful saves log the PNG path.

The Ctrl+B development runner sets `MAAGE_SCREENSHOT_SESSION` to a unique
run identifier. Screenshot filenames include that identifier. When the
game process exits, the profiler ZIP collects only matching screenshots
from the instance's **default private** `screenshots` folder under
`screenshots/`, plus the diagnostic logs/CSVs and a `run.json` file
listing the images. Custom/shared screenshot folder mappings are not yet
automatically discovered by the PowerShell archiver.
